# 调研:uTools「超级剪贴板」图片处理与容量策略

> 调研日期 2026-09-03。两个版本:开源 v1(GitHub ZiuChen/ClipboardManager,最后提交 2023-05)与闭源 v3.6.4(插件市场当前版,文档 super-clipboard.github.io)。

## 开源 v1 的做法(源码事实)

- **读取优先级** `pbpaste()`(`src/global/initPlugin.js`):文件 → 文本 → 图片。有文本(非空白)就记文本,不再看图片;注释标注 `clipboard.readImage() // 大图卡顿来源`
- **图片存储**:整张图 `toDataURL()` 成 base64 **直接塞进一个 JSON 文件**(整库单文件,每次变更全量 `writeFileSync`);无缩略图、无单独文件、无尺寸上限
- **去重键**:`md5(data)`,图片即 base64 串的 md5;命中则只刷新 `updateTime` 上浮
- **容量策略**(`src/data/setting.json` 默认值 + `Setting.vue` 选项):
  - `database.maxsize` 默认 **800 条**,可选 500~1000;图文文件**共用**总容量,超出时从尾部弹出,**收藏项回栈**不删
  - `database.maxage` 默认 **14 天**,可选 1/3/5/7/14/31;**仅启动时**按 `updateTime` 清理,收藏豁免
- **列表渲染**:`<img :src="item.data">` 直接渲染整张 base64,CSS `max-height: 100px; max-width: 85%`(图片行比文本行高,行高随内容)
- **写回**:`utools.copyImage(dataURL)` + 模拟 Ctrl/Cmd+V

## 闭源 v3.6.4 的做法(官方文档事实)

- 列表缩略图来自 `ClipMeta.preview`:**边长 ≤ 200px 的 base64**,「首屏零 IO」;原图 body 单独存(`clip-body/<hash>`),按需 `getClipBody` 取 bytes + mime
- 去重仍按**图片字节 hash**(OCR 结果也按 hash 内容寻址)
- 容量:「不限制条数与过期时间,支持上万条」是宣传口径;实际提供 **自动过期 7/14/30/60/120 天** 与 **最大数量上限** 两个开关,**均只在启动时执行**,置顶/收藏豁免;未见单图体积上限或图片独立配额
- 列表布局:左列时间、中列「文本预览 / 图片缩略图 / 文件名」;Tab:全部/文本/图片/文件/置顶/收藏
- 详情预览面板显示完整尺寸,支持旋转/翻转/缩放/另存为

## 对本项目的启示

| 维度 | uTools 做法 | 本项目现状 / 可借鉴点 |
|------|------------|------------------|
| 容量 | 图文共用总条数(v1 800 / v3 可配),叠加天数过期;无图片专属配额,无单图上限 | 已有 `MAX_HISTORY_ITEMS = 500` 共用容量,与 uTools 一致;可不做图片独立配额 |
| 图片存储 | v1 base64 进 JSON(被自己标注为卡顿来源);v3 原图与预览分离、预览 ≤200px | 已规划原图 + 缩略图落盘、库存路径,与 v3 方向一致,优于 v1 |
| 去重 | 内容 hash(图片字节) | 已规划 `content_hash = blake3(像素)` |
| 文本/图片并存 | v1 文本优先(文件 > 文本 > 图片) | 可沿用「有文本记文本」 |
| 清理时机 | 启动时批处理 | 现状 `prune` 每次入库后跑,更即时;需补文件删除 |
| 列表呈现 | v1 图片行加高 ≤100px;v3 中列缩略图(≤200px 源) | UX 决策项,两种先例都有 |
